# Minor UI change

Use for one narrow, low-risk interface update with an accepted design baseline and clear acceptance criteria. Route broad navigation, task-flow, brand, or product-model changes to their discovery workflow.

## Work

1. Pin the brief, affected screens and states, accepted design baseline, requirements, and active product decisions.
2. Make the smallest coherent UI change. Preserve unrelated product behavior and identify affected responsive, loading, empty, error, permission, and recovery states.
3. Ask Design QA & Accessibility to inspect the exact candidate independently for requirement fit, state coverage, accessibility and baseline continuity.
4. Ask the Design Director to accept, request revision, or mark the result incomplete using the candidate and evaluation versions.
5. Publish the accepted candidate, baseline delta, evaluation and decision in `minor_ui_design_package`.

## Complete when

The accepted package identifies exact candidate and baseline versions and a reviewer execution distinct from the author. A changed candidate invalidates affected review evidence and requires a new run.
