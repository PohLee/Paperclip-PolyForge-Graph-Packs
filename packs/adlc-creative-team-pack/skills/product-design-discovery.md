# Product design discovery

Use this workflow for substantial changes to an existing product interface when the user need, task structure, or interaction model still needs exploration.

## Work

1. Pin the sourced creative brief, accepted requirement and active product decisions. Keep product scope fixed; record proposed scope changes for the authorized product owner.
2. Research user needs, usage context, constraints, relevant patterns and applicable design principles. Cite sources, sample limits and uncertainty in `product_design_research`.
3. Create two structurally distinct wireframe directions from the same requirements and evidence. Record task flow, information hierarchy, key states and tradeoffs in separate versioned `wireframe_direction` artifacts.
4. Submit both directions without author labels to independent review. The review checks usability, requirement fit, accessibility and the same predeclared comparison criteria; it retains scores and rejection reasons.
5. Ask the Design Director to promote A, B, both, or request revision. Freeze a `product_design_direction` that references the exact research, wireframes, evaluations, requirements and decision.

## Complete when

The promoted direction is versioned, sourced and tied to all review and decision references. Missing user evidence remains an explicit unknown; it is never simulated as research. If the evidence cannot support a direction, end as incomplete and state the exact gap.

Revisions start a new run from updated evidence or requirements. Prior artifacts and reviews remain linked to the versions they assessed.
