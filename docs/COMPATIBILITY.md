# Pack compatibility gate

Each Pack declares a Core semver range, graph/decision/evidence contract versions, and versioned capabilities. Release metadata identifies the deterministic payload in `dist/<pack>/<version>/pack.json`: SHA-256 covers the JSON bytes excluding `release`, avoiding a self-referential digest. The current releases carry `status: candidate` and `builtAt`; tags and remote publication are separate actions.

The current collection contains ADLC `adlc@0.3.2`, Marketing `marketing@0.0.4`, and ADLC Creative Team `creative-team@0.3.2`. Creative Team declares Core `>=0.8.4 <0.9.0` with graph, decision and evidence contracts at version `1`; its release tag is `creative-team/v0.3.2`. The new brand identity production workflows currently support English only.

Test a pinned, extracted Core source artifact, not a mutable sibling checkout. The artifact must contain `src/core/index.mjs` and its imports; the full suite also needs `src/plugin/review-context.mjs`. Its required runtime dependencies, including `semver` for the current Core compatibility module, must be present in the artifact or resolvable in its installed environment. The current contract artifact contains `src/core/` and that review-context module. It does not certify every host plugin module. Compute the sorted file-tree digest as relative path, NUL byte, file bytes for each file with `scripts/test-compatibility.mjs --core-artifact <path> --print-digest true`; save that digest as the pinned expected value. The test script checks the expected digest and Core runtime version before registration, and records the Core/Pack digest tuple and result in `dist/compat-reports/`.

```powershell
node scripts/test-compatibility.mjs --core-artifact <extracted-Core-0.8.6-artifact> --core-digest sha256:<tree-digest> --core-version 0.8.6
node scripts/test-compatibility.mjs --core-artifact <extracted-Core-0.8.6-artifact> --core-digest sha256:<tree-digest> --core-version 0.8.6 --full-suite true
```

Core 0.8.7 is the current compatibility target for the current source releases. Core 0.8.6 is the prior release; Core 0.7.x is the previous ADLC 0.1.10 compatibility baseline. ADLC 0.2.0 and Marketing 0.0.1 require `>=0.8.0 <0.9.0`. ADLC 0.2.1 requires `>=0.8.1 <0.9.0`; only its `verification@0.1.4` Graph requires `shadow-review-execution@>=1.0.0 <2.0.0`. The Core 0.8.0 candidate result and the ADLC 0.2.0/0.2.1 and Marketing 0.0.1 digests below are retained historical local results, not published releases. The full behavioral suite tests the ADLC to Marketing release receipt, provenance, contract version, project and target version boundaries.

The host supplies verified release events, sourced metrics, Dashboard read models and independent Shadow sessions only when its implementation actually supports them. The verification QA Shadow is required before dispatch; a pure Core Graph test advertises the capability only as a fixture and does not test the host dispatch lifecycle. A host integration test must exercise the accepted and non-accepted Shadow outcomes. Other optional capability declarations do not imply execution. The host rejects unsupported actions with an audit reason, and Marketing outcome review records unknown when metrics lack a verified source.
