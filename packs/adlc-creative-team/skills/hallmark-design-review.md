# Product-specific page review

This is a self-contained Creative method informed by Hallmark, not the upstream executable skill. It requires no external repository. Approved brand, selected concept, scope and Pack decision rules remain authoritative.

## Procedure

1. Pin the subject and brief. State the visitor's primary job and identify supplied content, licensed assets and missing proof. Never fabricate customer quotes, metrics, endorsements or product screenshots.
2. Explain how the page structure serves that job. Identify one memorable, product-relevant element grounded in available material. Remove redundant decoration only within authorized scope; do not impose a house theme or a fixed section count.
3. Check that hierarchy, typography, spacing and color reinforce that structure and the approved system. For work screens prioritize task controls and meaningful data over promotional composition.
4. On an authorized redesign, inventory links, form fields, handlers and destinations before changes, then verify they still work. An audit produces findings only.
5. Inspect rendered desktop and narrow layouts when the harness provides rendering. Separate visual judgment, reproducible defects and untested behavior. Run available functional checks; missing render evidence means unverified, not passed.
6. Report each finding with exact subject version, evidence, impact and a bounded recommendation. Keep taste preferences distinct from contract failures; route acceptance through the existing independent reviewer and owner decision.

## Optional harness tool

Only when requested or explicitly authorized by host policy, the harness may install a reviewed Hallmark release outside the Pack and expose its checker. Resolve the installed location and supported arguments through the harness; never assume a repository checkout exists here. A supported invocation may be `node <installed-skill>/scripts/sloplint.mjs <authorized-target> --render`. The harness owns dependency installation, browser access, network permissions, time limits and cost approval. Do not run remote installers, copy upstream code into this Pack, or enable image services from an environment key alone.

Record the actual tool version, target, invocation, exit status, findings and render evidence. A checker warning is evidence to assess, not authority to waive Pack contracts or rewrite a brand. If the optional checker is absent, use the procedure above and mark only tool-specific checks unverified. Required rendering or functional evidence still blocks the corresponding completion claim.

Done when a scoped, evidence-linked review is delivered with unresolved issues and capability gaps explicit. This Skill does not itself approve, publish or adopt the design.
