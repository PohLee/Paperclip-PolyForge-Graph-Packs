# UI prototype experiment

Use only when comparing up to two shortlisted UI candidates can resolve a stated product-design uncertainty. A prototype is a test instrument, not an approval by itself.

## Work

1. Pin the exact candidate set, finalist versions, comparison criteria and the question the experiment must answer.
2. The Design Director chooses direct selection, prototype comparison, revision, or incomplete. Direct selection requires a recorded reason that the existing evidence is sufficient.
3. For prototype comparison, build each finalist in a separate execution context against the same tasks and interaction states. Do not give one prototype extra scope or polish.
4. Record observed user evidence, task outcomes and limitations against exact prototype versions. If no users or suitable evidence are available, mark the comparison unknown; do not infer a winner from a synthetic test.
5. Ask the Design Director to select one exact frozen candidate, request revision, or mark the result incomplete. Freeze the `ui_design_selection` with the prototype comparison or no-prototype rationale and decision.

## Complete when

The selection cites a current candidate-set version, selected candidate version, comparison criteria and either an evidence-backed prototype comparison or an explicit rationale for direct selection. Human preference remains a human decision when the active decision mode requires it.
