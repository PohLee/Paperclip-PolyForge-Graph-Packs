# Concept sprint and gallery

First freeze one brief and comparison basis. Respect count 3–5; default to 3 and expand only for real uncertainty. Give each candidate a distinct design hypothesis, stable ID, equal content, target dimensions, and comparable finish. Generate actual static images; inspect each image for decoding, subject, and duplication. Deliver one HTML gallery with each static image, an 80–120 word introduction, three key choices, a suitable use case, and one honest tradeoff. Include zoom and comparison only; the gallery does not represent interactive prototypes. If image generation is unavailable, report the capability gap instead of substituting text or a product page.

## Procedure and completion

1. List the shared acceptance criteria and the variable axis from explorationMode. Sketch a hypothesis for each direction before requesting images; keep the comparison fair.
2. Use only authorized host image generation and artifact storage. Record provider receipt, prompt/brief version, asset ID and actual dimensions. Upstream design references are not generation providers.
3. Inspect the generated files, not just prompts. Check the requested subject, legible hierarchy, real differences, licensed material and consistency with the brief. Reject broken, duplicate or irrelevant candidates.
4. Assemble the gallery with exact candidate IDs, accessible descriptions and no hidden winner. Compare tradeoffs against the same criteria; selection remains an authenticated human decision.

Done when all requested images and the single gallery pass artifact checks and are available to the reviewer. Missing image capability or evidence leaves the set incomplete; written concepts cannot satisfy the image contract.
